# SENTRY-V0.3.3-CODEX-EXECUTION-AUTHORITY-001

## Objective

Replace the resident SENTRY Codex launcher's unrestricted execution posture with a host-enforced, risk-tiered authority boundary while preserving the persistent Codex thread, native read/search reasoning, and the SENTRY MCP surface.

## Required boundary

- Preserve the existing manual unrestricted development profile as a non-resident operator tool.
- Run resident SENTRY under a dedicated Codex permission profile with root-deny/minimal-read filesystem policy, bounded writable workspace, and command network disabled.
- Keep native Codex web search available while disabling apps, plugins, browser automation, computer use, and unmanaged MCP servers.
- Route sensitive desktop/file actions through an exact, request/thread/restart-bound
  host broker. A clear current-turn operator request executes directly after
  validation and audit. Only an explicit request to wait/ask/show/prepare first,
  or a genuinely unresolved material detail, creates a one-use pending dialogue.
- Audit every non-read execution attempt without storing prompts, ambient speech, secrets, or file contents.
- Preserve persistent thread continuity and automatic compaction while keeping durable memory disabled.

## Exclusions

- No expansion of physical perception, reminders, weather, routines, or voice semantics.
- No browser automation, computer-use runtime, arbitrary plugin/app inheritance, or general unrestricted shell in the resident profile.
- No Obsidian vault creation or persistent personal-memory implementation.
- No destructive Git recovery and no loss of the existing persistent production thread.

## Acceptance

The automated and adversarial matrices plus the owner-selected bounded live
proof must pass; schema remains 9; the production resident service must use the
restricted profile; the manual development profile remains available; Authority,
Notion, and Git must agree; and the final tree must be clean. The operator waived
artificial deferred-action live drills after the successful direct-action proof;
those dormant paths remain deterministic, fail-closed, and regression-covered.

## Stop conditions

Stop rather than claim qualification if the installed Codex runtime cannot technically enforce sensitive-read or command-network isolation, profile restrictions are bypassed on thread resume, unmanaged apps/browser/plugins remain callable, the confirmation broker cannot be made exact and replay-safe, audit omits a non-read path, or qualification requires broadening authority.
