# V0.2 Event-Triggered Reminders

SENTRY supports one narrow reminder: an explicit request to remind the primary user the next time they are first confirmed in a future distinct office presence session.

## Contract

Supported requests include:

```text
Remind me next time I come into the office to call Mom.
Do I have an office reminder?
Cancel my office reminder.
```

The stored body is only the requested message, normalized and limited to 120 characters. Scheduled, recurring, timed, weather-triggered, and leave-the-house reminders are rejected deterministically. Create, query, and cancel use zero Luna calls.

The schema-v8 `event_reminders` table permits one pending reminder for `primary_user` / `office` / `next_primary_user_office_session`. Creating it during an open session records that session; a later identity observation in the same session cannot trigger it. A future valid `person.identified` event must belong to a different session.

## Delivery safety

Physical, source-health, session, freshness, restart, and startup gates run before reminder eligibility. A valid explicit reminder takes priority over unsolicited acknowledgement/weather behavior and is not suppressed by the acknowledgement preference. It still respects the global enable and speech-busy gates.

Before speech, the reminder and its `proactive_actions` record are atomically claimed. Successful local speech marks it `delivered`; confirmed failure marks it `failed`. A claimed reminder found after restart is conservatively marked `failed` with `unknown_delivery_after_restart` and is never replayed. Replays and processor restarts cannot deliver it twice.

Delivery is deterministic local speech (`Reminder: <message>`) and does not invoke Luna. No reminder body is sent to Luna, and no audio, image, embedding, or biometric data is stored.

## Local API and operations

The existing localhost-only state API provides:

```text
GET  /v1/reminders
POST /v1/reminders
POST /v1/reminders/{id}/cancel
```

The CLI conversation path is `tools/sentry_ask.py`; its reminder intent selection is deterministic and idempotent by request identifier. The production database remains local SQLite with the existing Atlas snapshot mirror. Qualification used isolated databases; production reminder count remains zero.

The accepted contextual weather path remains unchanged: a reminder claims the source event before weather can be considered, so one physical identity event cannot produce both reminder and unsolicited weather speech. Routine facts remain outside the proactive packet, and perception remains at zero Luna calls.
