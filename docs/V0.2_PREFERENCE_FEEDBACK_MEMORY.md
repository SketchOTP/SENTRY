# V0.2 Preference + Feedback Memory

This slice stores one explicit, reversible behavior preference for the primary
user: `proactivity.primary_user_session_acknowledgement`, with values `allow`
or `suppress`. No row means `default`, which preserves the accepted M5 policy.

The schema-6 `preference_events` ledger is append-only. `set` and `clear`
operations retain source surface, request ID, timestamp, and the superseded
event. The current value is derived from the latest valid event. Repeating a
source/request ID is idempotent. `proactive_feedback` attaches only to a real
persisted M5 action; `helpful`, `not_helpful`, and `too_frequent` are recorded
without changing policy, while explicit `do_not_repeat` also creates the
bounded `suppress` preference.

Supported text commands are deterministic and use the existing `sentry_ask.py`
and localhost API. Supported examples include disabling/enabling greetings,
forgetting the greeting preference, asking about the saved preference, and
explicit feedback about one unambiguous delivered action from the last ten
minutes. Unsupported requests such as `Remember that I like blue` fail closed
and never enter a generic memory store.

M5 evaluates `user_preference` after event type, primary-user, freshness,
restart provenance, current occupied session, and source-health checks. A
suppressed valid candidate is persisted with `judge_invoked=false` and makes
zero Luna calls. Default or `allow` retains the existing dedupe/cooldown/budget
and optional Luna path.

Preference and feedback records are metadata-only and participate in the
existing local SQLite plus Atlas snapshot mirror. No raw audio, frames,
embeddings, biometric prototypes, unrestricted transcripts, or secrets enter
the ledger or API.
