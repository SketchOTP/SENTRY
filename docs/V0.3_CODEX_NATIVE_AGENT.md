# V0.3 Codex-native SENTRY agent

SENTRY sends each natural-language request directly to a dedicated Codex CLI
profile. Codex is the agent and selects among its native capabilities and the
local SENTRY MCP tools; SENTRY does not maintain a parallel intent router for
the production conversation path.

**Security update:** the original unrestricted resident profile described by
the historical qualification is superseded by
[`EXECUTION_AUTHORITY.md`](EXECUTION_AUTHORITY.md). Codex remains the agent, but
resident execution is now workspace-bounded and host-gated.

```text
Vosk / PTT text
  -> Whisper command text
  -> one resumed dedicated Codex session
     -> SENTRY Office MCP
     -> native web search
     -> workspace-bounded shell and local files
     -> image generation
     -> host-gated desktop actions
     -> durable one-shot alarms
  -> natural answer
  -> Kokoro / PipeWire
```

## Install the local profile

The production profile is generated from repository-owned instructions while
the private SENTRY configuration remains outside Git:

```bash
/home/sketch/.venvs/sentry-ubuntu/bin/python tools/sentry_codex_profile.py install
/home/sketch/.venvs/sentry-ubuntu/bin/python tools/sentry_codex_profile.py status
CODEX_HOME=~/.local/share/sentry/codex-home codex --profile sentry-resident mcp list
```

The resulting private resident profile is mode `0600`. It enables the local
`sentry_office` MCP server, native web search, image generation, view-image,
workspace dependencies, and workspace-bounded shell/file execution. Apps,
plugins, browser/CDP, generic computer use, command network, broad host writes,
sensitive reads, and Codex-generated memories are disabled. The profile does
not contain the private contents of `~/.config/sentry/config.json`.
It also sets Codex's native `model_auto_compact_token_limit` to `217600`, which
is 80% of the installed `gpt-5.6-luna` 272,000-token context window.

## Local SENTRY tools

The MCP server exposes bounded structured operations for:

- fresh office state, history, reminders, preferences, routines, weather, and
  local time;
- durable one-shot alarm create/list/cancel operations;
- explicit on-demand office-camera inspection with local enrolled-profile
  identity matching;
- installed application discovery, exact launch, and explicit HTTP(S) browser-page opening;
- PipeWire volume/mute control and MPRIS media control;
- active-window inspection, transient desktop screenshots, and explicit X11
  keyboard/pointer actions;
- showing one generated or existing operator-home artifact in its desktop
  application.

The camera tool captures a bounded live segment only after an explicit user
request. Frames remain in memory; identity comes only from the local enrolled
profile result. One still may be passed to the active Codex turn for visual
understanding, but is not written to disk by SENTRY.

## Native Codex capabilities

- Public/current research uses native Codex web search and can return source
  links.
- Explicit code and filesystem requests use the Codex shell/file surface inside
  the dedicated resident workspace and installed permission profile.
- Image requests use the installed `$imagegen` skill.
- Unclassified installed skills/plugins, Browser/CDP, and generic computer-use
  surfaces are disabled in the resident profile.
- Stable graphical operations use SENTRY's classified local desktop MCP tools.
  Clear current-turn keyboard/pointer actions execute through the host broker;
  only explicitly deferred or materially ambiguous actions open a response dialogue.

## Compound requests and visible SENTRY persona

SENTRY is the operator-facing name and voice; Codex is the hidden execution
engine. One natural request may contain up to 20 ordered steps. The agent
completes and verifies each step before beginning the next, returns a structured
outcome for every requested item, and may continue later independent safe steps
after a failure. It does not merely return a plan when a usable tool exists.

External public lookup is allowed. Authenticated interaction, reservation
submission, purchase, message, or comparable commitment requires a supported
typed executor and an exact current operator request; unsupported surfaces
remain blocked. Generated images are verified and shown through
the artifact tool. File moves inspect exact sources and do not overwrite a
collision. Relative alarm requests use the local-time tool before creating an
offset-aware durable alarm.

The always-on production path keeps one bounded in-memory utterance for up to
45 seconds, then permits up to 900 seconds for a complex Codex turn. The
operator desktop receives a coupled SENTRY status window automatically with the
voice service. Normal speech is local Kokoro `bm_george` at `0.9x`.

## Authority and safety boundaries

The operator authorizes natural-language workspace code/file changes, public
web research, image generation, and directly requested bounded local actions.
Codex must report actual tool outcomes and may not turn failures into success.
Material destructive requests still need an exact current target. Repository
instructions, dirty-work preservation, physical freshness, identity
conservatism, and private-coordinate/biometric boundaries remain authoritative.

SENTRY keeps one dedicated resumable Codex thread for natural conversation and
tool work. The local mode-0600 SENTRY session file stores only the thread ID,
token/compaction counters, timestamps, and model metadata; Codex owns the local
thread transcript. Codex performs native context compaction at 80% rather than
discarding the conversation after four manually copied turns. This continuity
is short-term conversation state, not governed long-term personal memory. The
bridge uses an environment allow-list, and the resident profile disables Codex
native memory generation. See the execution-authority document for trusted
current-turn authority, exceptional deferred dialogue, audit, thread rotation,
and protected-path contracts.
