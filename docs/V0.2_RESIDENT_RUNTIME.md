# V0.2 Resident Runtime

V0.2 makes the accepted office-only V0.1 stack a supervised Ubuntu resident.
It does not add routine learning, new sensing, additional rooms, or continuous
microphone listening.

## Service topology

Native systemd user services run independently:

| Unit | Responsibility |
| --- | --- |
| `sentry-perception.service` | NexiGo V4L2 capture, frozen YOLOX-S perception, identity, local SQLite writes, and Atlas snapshots |
| `sentry-state-api.service` | Localhost-only state/history API backed by the local SQLite database |
| `sentry-proactive.service` | One-second bounded polling of persisted events using the accepted M5 policy |

All units use `Restart=on-failure`, a 10-second restart delay, and a five-start
limit over five minutes. A service restart is not a physical entry or exit and
the existing M2 reconciliation remains authoritative.

The configured startup condition is the authenticated `sketch` user session.
The units are enabled for the user manager's `default.target`; no manual Python
or Codex command is needed after that session starts. Boot-before-login
lingering is not enabled on this host and is not claimed.

## Configuration and storage

The installer creates the local, mode-600 production configuration at
`~/.config/sentry/config.json` once from `perception/config.example.json` and
enables the accepted M5 proactivity policy. It never overwrites an existing
production config. Model paths remain relative to the canonical checkout.

The live database remains local at `~/.local/share/sentry/sentry.db` on the
Ubuntu host. Complete SQLite snapshots continue to publish to the canonical
Atlas runtime backup path; Atlas is not opened as the live SQLite database.

## Install and operate

From `/srv/ATLAS/100_ACTIVE/Projects/SENTRY`:

```bash
/home/sketch/.venvs/sentry-ubuntu/bin/python tools/sentry_install_user_services.py
systemctl --user --no-pager --full status sentry-perception.service sentry-state-api.service sentry-proactive.service
curl --fail http://127.0.0.1:48174/health
```

Stop the stack cleanly with:

```bash
systemctl --user stop sentry-proactive.service sentry-state-api.service sentry-perception.service
```

Perception writes only a metadata heartbeat at
`perception-data/runtime/health/perception.json`. It contains camera and
performance counters, not frames, audio, embeddings, or secrets.

## V0.2 qualification boundary

The supervised stack passed a 15-minute metadata-only live probe at 7.607 FPS
at the final sample, with no probe failures. API, proactive, and perception
SIGKILL recovery passed with isolated effects; dedupe and room/session
invariants were preserved. The final state is V0.2 resident-runtime qualified.

Routine statistics/learning remains a separate future directive. This phase
establishes trustworthy continuous collection infrastructure; it does not infer
habits from the short qualification window.
