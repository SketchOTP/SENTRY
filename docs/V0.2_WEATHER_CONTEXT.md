# V0.2 weather context

SENTRY's weather context is a read-only, bounded National Weather Service
adapter. It is external context, not physical presence evidence.

## Contract

The operator must explicitly configure `weather.enabled`, an IANA timezone,
and latitude/longitude in the local mode-0600 production configuration. SENTRY
does not infer a location. The checked-in example leaves weather disabled and
coordinates unset.

`tools/sentry_weather.py refresh` discovers and caches the NWS point resources,
normalizes current observation data, the next 24 hours of hourly forecast, and
active alerts, then persists one schema-v7 snapshot in local SQLite. A complete
SQLite snapshot is mirrored to Atlas through the existing M2 backup path. The
live database is never opened on the Atlas SSHFS mount.

The point mapping is cached for 24 hours. Refreshes use a stable SENTRY
User-Agent and bounded retries for rate limits, server errors, and transient
network failures. A failed refresh keeps the last good snapshot and does not
extend its freshness deadline.

`GET /v1/weather` exposes only normalized, bounded metadata and reports
`fresh`, `stale`, or `unavailable`. It omits precise coordinates and provider
resource URLs. Weather questions use deterministic intent routing and at most
one existing low-effort Luna turn. Stale or unavailable context returns an
explicit limitation without a Luna call. Weather is not included in M5
proactive facts, and weather failure cannot affect perception, identity,
physical history, routines, or preference memory.

## Resident behavior

`sentry-weather.service` and `sentry-weather.timer` are independent user-systemd
units. The timer is installed with the resident stack but is enabled only when
the local production config explicitly enables weather and supplies coordinates.
With `Linger=no`, this remains an authenticated user-session service rather than
a boot-before-login service. The timer never controls the other SENTRY units.

## Current production status

The real production configuration currently has no explicit weather coordinates,
so production weather remains disabled and the refresh command reports
`WEATHER LOCATION CONFIG REQUIRED`. NWS transport and normalization are verified
with an isolated public-coordinate fixture; that fixture is not a claim about
the operator's local weather.
