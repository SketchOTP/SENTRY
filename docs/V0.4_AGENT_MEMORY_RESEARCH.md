# V0.4 Agent Memory Research

## Decision boundary

SENTRY now has two different continuity problems with different solutions:

1. **Working conversation continuity** belongs to Codex. SENTRY resumes one dedicated local Codex thread and configures native compaction at 217,600 input tokens, 80% of Luna's 272,000-token context window.
2. **Durable personal memory** must be a separately governed SENTRY capability. A compacted Codex transcript is useful conversational history, but it is not an authoritative personal-memory database.

The current work implements only the first item. No long-term-memory engine is installed or authorized by this record.

## Required SENTRY memory contract

Any V0.4 memory layer should expose a narrow tool boundary to Codex instead of replacing Codex as the agent runtime. Minimum host-owned operations should be conceptually equivalent to:

- `remember`: store an explicit operator-approved fact, preference, decision, or experience;
- `recall`: retrieve a bounded relevant set with source provenance;
- `correct`: supersede a prior memory without rewriting history;
- `forget`: invalidate or delete a selected memory with an audit record;
- `list_memories`: let the operator inspect what SENTRY believes it remembers.

Every durable item should carry an ID, type, subject, source surface/request, created time, source time where applicable, validity state, supersession linkage, sensitivity, and provenance. Memory writes must be host validated. Ambient microphone transcripts, camera streams, and arbitrary whole-conversation mining must not become durable memory automatically.

## Candidate assessment

| Candidate | Strength | SENTRY fit | Disposition |
| --- | --- | --- | --- |
| Hindsight | Self-hosted MIT memory service; retain/recall/reflect APIs; MCP and Codex integration; hybrid and temporal retrieval | Strongest ready-made benchmark candidate, but its default after-turn extraction conflicts with SENTRY's explicit-write and no-transcript-mining policy unless wrapped | **BENCHMARK behind a SENTRY governance adapter** |
| Mem0 | Apache-2.0 self-hosted memory with fact extraction, user/session/agent scoping, and vector retrieval | Simpler fact-memory candidate; still needs explicit write gates, provenance, correction, and deletion verification | **BENCHMARK second** |
| Graphiti | Apache-2.0 temporal knowledge graph with validity windows, episode provenance, and hybrid retrieval | Excellent temporal model, but materially heavier graph infrastructure and unresolved governance burden for a one-user one-room product | **REFERENCE temporal design; do not adopt first** |
| LangGraph memory | Clear semantic/episodic/procedural taxonomy and namespace/key stores | Useful design vocabulary, but adopting its agent runtime would duplicate/replace Codex | **REFERENCE only** |
| Letta | Apache-2.0 stateful-agent runtime with memory blocks and archival memory | Full agent runtime conflicts directly with Codex-as-brain | **REJECT as runtime replacement; reference memory-block UX** |
| SENTRY-native SQLite | Existing trusted local persistence, migrations, provenance, auditability, correction/forgetting under host control | Lowest infrastructure and strongest governance fit; semantic retrieval quality must be measured rather than assumed | **BUILD fallback/baseline for comparison** |

## Recommended next qualification

Run a bounded V0.4 memory bake-off, not a production rollout:

1. Define a fixed corpus of explicit facts, preferences, corrections, temporal changes, and forget requests.
2. Compare a SENTRY-native schema, Hindsight behind an explicit-write adapter, and Mem0 behind the same adapter.
3. Measure retrieval precision, contradiction handling, temporal correctness, correction/forget effectiveness, latency, local resource cost, restart behavior, and operator inspectability.
4. Reject any system that requires uploading private memory, silently retaining full transcripts, or bypassing SENTRY's provenance and mutation controls.
5. Keep Codex as the planner/executor. The selected memory system becomes a callable SENTRY tool, not another assistant.
