# V0.3 — Host-Bounded Read-Only Web Access

SENTRY's conversational planner may request three host-owned read operations:

```text
search_web(query)                 → bounded public-source extracts
read_web_page(user-supplied URL)  → one bounded public-page extract
get_public_weather(place, date)   → normalized public forecast
```

Luna receives only the typed tool catalog and the bounded result facts. It
never receives a browser, socket, shell, filesystem, credentials, or a generic
HTTP client. The host validates every request and performs the actual network
read.

## Read-only boundary

- HTTP(S) only; standard ports only; redirects are revalidated.
- DNS results must all be globally routable. Loopback, private, link-local,
  multicast, and otherwise non-global destinations are rejected.
- URLs with credentials, non-readable content types, and oversized responses
  are rejected. The page-response cap is 750 KiB and the model-visible extract
  is capped at 4,000 characters per source.
- No authentication, cookies, forms, uploads, purchases, posts, private-network
  access, local file access, or network writes are available.
- External page text is untrusted reference material, never executable
  instruction. Synthesis must cite the supplied fact IDs and must not disclose
  SENTRY-local identity, history, reminder, coordinate, or secret data.

Search uses a public no-credential discovery feed and independently validates
each returned source. If a public destination cannot be read, a clearly marked
source-attributed search snippet may be retained; private or invalid result
URLs are discarded before any fallback fact is produced.

## Place/date weather

`get_public_weather` is a narrow host adapter around public Open-Meteo
geocoding and forecast endpoints. It sends only a place explicitly stated by
the user, supports `today`, `tomorrow`, or an ISO date within the next 15 days,
and returns location label, local date/timezone, condition summary,
Fahrenheit range, and maximum precipitation probability. Provider coordinates
and URLs are omitted from Luna-visible facts.

Configured **home** weather remains the existing private NWS cache tool. The
planner must not turn SENTRY's private home location into a web query. This
keeps the local config coordinate private while the independent weather timer
maintains cache freshness.

## Privacy and persistence

Web extracts are request-scoped tool facts only. They are not stored as a web
archive, memory, embedding, or conversation transcript. Search, public weather,
and page reading make no Luna call by themselves; the normal bounded planner
and synthesis calls remain the only Luna invocations for a user request.
