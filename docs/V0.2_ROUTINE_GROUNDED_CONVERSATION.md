# V0.2 — Routine-grounded conversation

This slice extends the qualified M4 query path with a narrow, deterministic
route for questions about usual or learned office behavior. It does not change
physical presence, identity, routine statistics, M5 proactivity, or the
localhost-only API boundary.

## Routing and evidence

`tools/sentry_routine_intent.py` recognizes habitual language and maps it to
one of the four schema-v5 routine types and an explicit scope (`all_days`,
`weekday`, `weekend`, or a named weekday). Questions without habitual language
remain on the physical-history path. Unsupported habitual activity or causal
questions fail closed without a Luna call.

Routine questions retrieve `/v1/routines` only after the normal health check.
The fact packet includes only the selected metadata-only snapshot(s), with
stable IDs such as `routine:office_session_start_time:weekday`, plus the
current physical state needed to prevent a routine from overriding present
truth. Raw sessions are not substituted for a missing routine snapshot.

The existing response contract remains:

```json
{
  "answer": "...",
  "grounding": "supported | partial | unavailable",
  "fact_ids": [],
  "limitations": []
}
```

## Maturity wording

- `insufficient`: deterministic response explains that sparse history cannot
  support a reliable routine claim; no Luna call is made.
- `observed`: at most one low-effort Luna turn may describe a tentative pattern
  with sample and distinct-date evidence.
- `stable`: at most one low-effort Luna turn may use usual/typical language,
  while retaining the relevant variability and evidence counts.

Room-session timing is not presented as the primary user's exact arrival;
first identity confirmation is not exact entry; room duration/absence is not
automatically personal duration/absence. Routine statistics never override
current physical state or persisted physical history.

## Qualification result

The implementation was qualified on 2026-08-30 and is recorded in the final
pushed Git commit and Authority outcome. Focused routine-conversation tests
passed `17/17`; the full Ubuntu regression passed `129/129` with the existing multiprocessing fork
deprecation warning. Deterministic fixtures cover intent/scope routing,
insufficient/observed/stable packets, unsupported activity, unknown fact
rejection, routine endpoint failure, physical-query isolation, and the
current-state-versus-typical-pattern contradiction.

The actual resident database/API remained healthy at schema 5 with Atlas
mirror `ok`. Its 40 latest snapshots remain `insufficient`; natural history is
sparse, so live routine questions returned explicit evidence-insufficient
answers and made zero Luna calls. M5 receives no routine facts, and continuous
perception remains at zero Luna calls. The accepted reactive voice path uses
the same `sentry_ask.py` query surface by code path; no new microphone proof
was required.
