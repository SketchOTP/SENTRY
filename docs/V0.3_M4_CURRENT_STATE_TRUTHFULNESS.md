# V0.3 M4 Current-State Truthfulness

## Purpose

M4 distinguishes a healthy local database from fresh physical observation. A
persisted room snapshot is history; it is not evidence of what is happening
now after perception stops.

## Localhost health contract

`tools/sentry_state_api.py` accepts these production arguments:

```text
--perception-heartbeat <path>
--perception-freshness-seconds 75
--display-timezone America/New_York
```

`GET /health` preserves `ok` and `db_available` as database health. It also
returns a separate `perception` object with:

```text
status: fresh | stopped | stale | missing | malformed
heartbeat_updated_at
age_seconds
process_alive
camera_state
room_state
current_physical_available
reason
```

`current_physical_available` is true only for a parsed, alive heartbeat no
older than the configured limit and an `online` camera source. A fresh
`degraded` or `offline` camera remains current-occupancy unavailable.

## Grounding boundary

When current physical evidence is available, M4 may use:

- `current-room-state`
- `current-room-people`
- `current-open-session`

When it is unavailable, those facts are omitted. Historical facts remain
available, including room sessions, semantic events, primary-user
identifications, last-confirmed-empty evidence, routines, and weather.

Clear present-tense occupancy, identity, and live-duration questions return a
deterministic unavailable answer with zero Luna calls when no current physical
evidence exists. Historical records never establish present occupancy.

## Local-time contract

Persisted source timestamps remain offset-aware UTC/ISO values. The fact packet
adds deterministic `*_local_display` presentation values using Python
`zoneinfo` and the configured IANA timezone. Ordinary answers use local
12-hour AM/PM form, including the date and timezone abbreviation when needed.
Luna receives the display value and is instructed not to calculate offsets from
raw timestamps.

## Boundaries

This repair does not change schema 8, physical history, perception/identity,
routine/weather/reminder/preference semantics, M5 policy, or the preserved
uncommitted V0.3 always-on voice implementation. Continuous perception remains
at zero Luna calls.
